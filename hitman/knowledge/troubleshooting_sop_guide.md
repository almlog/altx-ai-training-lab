# 社内運用保守・障害対応トラブルシューティングガイド (SOP Knowledge Base)

本文書は、本番リリース作業およびシステム運用において異常停止・想定外事象が発生した際の対応基準および調査手順を定めたナレッジベースです。

---

## 1. ディスク容量枯渇時の対応 (Step 1-1 関連)

### 発生事象
`/backup` ディレクトリの空き容量が10GB未満（使用率95%以上）となり、事前バックアップが取得できない。

### 対処手順
1. **古いアーカイブの整理**:
   過去30日以上前のバックアップアーカイブを確認し、最新3世代を残して退避・削除する。
   ```bash
   find /backup -name "app_*.tar.gz" -mtime +30 -exec rm -f {} \;
   ```
2. **ローテーションログの削除**:
   `/var/log` 配下の圧縮済み過去ログ（`*.gz`）をクリーンアップする。
   ```bash
   journalctl --vacuum-size=500M
   ```
3. **容量再確認**:
   `df -h /backup` で空き容量が10GB（Avail >= 10G）以上になったことを確認し、作業を再開する。
   空き容量が確保できない場合は作業を中断し、インフラ担当者へエスカレーション（E-1）を行う。

## 2. データベース更新異常・不整合時の対応 (Step 3-3, 3-4 関連)

### 発生事象
- 事前SELECT結果が0件（Empty set）
- 更新SQLに対象外テナントの条件が含まれる（要件不一致）
- UPDATE文実行時に Lock wait timeout または デッドロックが発生した

### 対処手順
1. **0件または要件不一致時**:
   直ちに作業を中断し、エスカレーションゲート（E-1）へ移行する。依頼元仕様書と照合し、開発リーダーの承認および判断根拠（修正SQLの承認チケット番号等）を取得するまで本番適用を行ってはならない。
2. **ロック待ち発生時**:
   バックグラウンドで他トランザクションがレコードを掴んでいないかプロセスリストを確認する。
   ```sql
   SHOW PROCESSLIST;
   SHOW ENGINE INNODB STATUS;
   ```
3. **ロールバック判断**:
   SQL適用後に想定外の件数が更新された場合、直ちにトランザクションをROLLBACKするか、ステップ R-1（バックアップからの旧状態復元）を実施する。

## 3. サービス起動失敗・ヘルスチェック異常時の対応 (Step 4-1, 4-2 関連)

### 発生事象
`systemctl start my-app.service` 後に起動せず、または `curl http://localhost:8080/health` で HTTP 200 以外のステータス（500 Internal Server Error, 502 Bad Gateway）が返却される。

### 対処手順
1. **サービス詳細ステータスの確認**:
   ```bash
   systemctl status my-app.service -l --no-pager
   ```
2. **システムログ（直近100行）の調査**:
   ```bash
   journalctl -u my-app.service -n 100 --no-pager
   ```
   主な原因:
   - `.env` ファイルのパーミッション不足、または環境変数不備
   - DB接続エラー（認証情報誤り、マイグレーション未完了）
   - ポート競合（8080ポートが旧プロセスに残っている）
3. **ロールバックの即時判断**:
   起動試行から10分以内に原因究明・復旧できない場合は、本番影響を最小化するため、迷わずロールバック手順（ステップ R-1、R-2）へ切り替える。

## 4. エスカレーション基準と連絡体制 (Step E-1 関連)

### エスカレーション必須事象
- 破壊的クエリ（DROP, TRUNCATE）の混入
- WHERE句なしの更新・削除クエリ
- リリース停止可能枠（メンテナンス枠）の残時間が30分を切った場合
- 事前バックアップ取得不可

### 運用体制の切り替え基準
- **通常モード復帰**: 手順書通りの原因（タイポや簡単な手順修正）が特定され、合意された場合。
- **特別モード（2人体制）**: 暫定パッチ投入や緊急回避対応を行う場合。作業リーダーまたは上長とペアを組み、投入コマンドの相互復唱・ダブルチェックを行うこと。
